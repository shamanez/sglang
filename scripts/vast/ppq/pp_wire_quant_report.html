8-bit Activations on the Pipeline Wire

Qwen/Qwen3.6-35B-A3B · 4× RTX 5090 · sglang dev @ 20b8500e5 · run 2026-08-21

What this experiment is

We asked what happens to the currently hosted model — Qwen/Qwen3.6-35B-A3B, a hybrid MoE with 30 gated-delta-net (recurrent) layers and 10 full-attention layers among its 40 layers — when the intermediate activations crossing pipeline-parallel stage boundaries are quantized to 8 bits at serving time. This is the narrow object of our literature survey: a tensor produced and consumed inside one forward pass, never retained across decode steps. The survey's sharpest finding was that no paper in the field measures whether such compression error accumulates across decode steps; this experiment measures exactly that, on a model whose recurrent GDN state gives error a mechanism to persist.

SGLang had no support for this (the PP wire is unconditionally the model dtype), so we added a research knob, SGLANG_PP_ACTIVATION_WIRE_QUANT=int8|fp8: just before the scheduler sends the PP proxy tensors (hidden_states and residual, each [tokens, 2048] bf16), they are quantized per-token (symmetric absmax int8 + one float32 scale per token) and dequantized right after the receive. The wire format is self-describing, the transform is out-of-place, and the model, CUDA graphs, and all math see bf16 exactly as before — with the flag unset the code path is byte-identical to upstream. Wire bytes drop 1.96× (8,192 B → 4,100 B per token per tensor per boundary). Isolated kernel roundtrip error: 0.66% max per-token relative error (int8), 3.8% (fp8, unmeasured end-to-end here).

Four configurations on the same 4× RTX 5090 box (PCIe, no NVLink): tp2×pp2 (1 pipeline boundary) and tp1×pp4 (3 boundaries), each with the wire in bf16 (control) and int8. The production deployment (tp4) has zero pipeline boundaries, so PP topologies were launched for the experiment and the production server restored afterwards. The bf16 controls matter: pp2-bf16's agreement with itself calibrates server nondeterminism (continuous batching makes borderline argmaxes flip), and pp4-bf16 isolates the topology change from the codec.

Metrics and why these

Teacher-forced NLL (WikiText-2 test, 24 windows × 1,024 tokens, 24,576 scored tokens) is the highest-resolution quality probe — it detects representational damage far below task-accuracy noise. GSM8K exact-match (100 test questions, greedy, thinking disabled) is the task-level check. The positionwise probe is the accumulation instrument: 12 fixed 256-token continuations were generated greedily once by the baseline, then every config teacher-forces the same trajectories and we record, at each decode position, the NLL of the reference token, whether the config's argmax agrees with the reference, and the top-5 distribution (for a truncated KL). If wire error compounded through the recurrent state, these curves would degrade with position; a flat gap means per-step, non-accumulating noise. bench_serving (48 prompts, 1,024 in / 256 out, concurrency 16) gives TTFT, inter-token latency, and throughput.

Findings

1 — Quality is unaffected, at one boundary and at three. Int8 on the wire moves WikiText NLL by +0.112% at pp2 and by +0.012% at pp4 relative to each topology's own bf16 control — and the pp4 delta is smaller despite three quantized hops, which says the deltas are dominated by run-to-run noise, not by the codec. The pure topology change (pp2-bf16 → pp4-bf16) moves NLL by −0.021%, bracketing the noise floor. GSM8K is 93/93/93/92% — the single dropped question at pp4-int8 is far inside the 95% Wilson interval (±5pts at n=100). Perplexity spans 6.641–6.657 across all four cells.

2 — No error accumulation over 256 decode steps. The probe's agreement-vs-position curves for the int8 configs sit inside the baseline's own self-agreement band (≈0.96–0.99, set by batching nondeterminism) at every horizon quarter, with no downward trend: pp4-int8 runs 0.964 → 0.987 → 0.986 → 0.982 across quarters while the baseline's self-agreement runs 0.974 → 0.988 → 0.981 → 0.982. Mean reference-token NLL over the probe is 0.2033 (baseline) vs 0.2037 (pp2-int8, +0.2%) vs 0.2065 (pp4-int8, +1.6%) — a constant small offset, flat in position. This is the direct measurement the surveyed literature lacks: through 30 recurrent GDN layers whose state persists across every decode step, per-token int8 wire error behaves as non-compounding per-step noise, not as drift.

3 — The wire compression pays exactly where the survey predicted: large transfers over slow links. On this NVLink-less box, halving prefill bytes cut median TTFT 23% at pp2 (406 → 312 ms, with output throughput up 4% to 1,011 tok/s) and 21% at pp4 (297 → 234 ms; mean TTFT −47%). Decode moves 1–16 tokens per hop, so the quant/dequant launch overhead slightly exceeds the bytes saved: median ITL +3.7% (13.4 → 13.9 ms) at pp2 and +3.4% (17.5 → 18.1 ms) at pp4. Net: a strict win for prefill-heavy/TTFT-sensitive serving; a wash-to-slight-loss for pure decode. A sharper implementation would quantize only extend-mode transfers.

Limitations

One model (and a small one on the wire: hidden size 2,048 means only 4 KB/token/tensor — models with 7–16 K hidden dimensions stress the link 3–8× harder and may benefit more). One horizon (256 steps). GSM8K at n=100 resolves only multi-point accuracy moves. The probe is teacher-forced on baseline trajectories, so it measures representational drift, not free-running behavioral divergence beyond the first disagreement. The nondeterminism floor (≈2–3% argmax flips) caps the resolution of the agreement metric. The fp8-e4m3 mode is implemented and unit-tested but not evaluated end-to-end. One mid-run OOM occurred (pp2-int8's probe stage, a marginal allocation failure after 100 GSM8K generations filled the radix cache at mem-fraction 0.85); the stage was rerun identically after adding an inter-stage cache flush to the harness — the OOM is a memory-headroom artifact, not a codec failure, but it is reported here because silence would overstate robustness.

Reproduction

Branch research/pp-activation-int8. Implementation: python/sglang/srt/managers/scheduler_pp_mixin.py + SGLANG_PP_ACTIVATION_WIRE_QUANT in environ.py (commit ea23f5b7a). Harness and driver: scripts/vast/ppq/ — run_all.sh runs all four configs and restores the production server; raw per-item JSON lives under /workspace/ppq/results/ on the box. Serving: sglang.launch_server --model-path Qwen/Qwen3.6-35B-A3B --attention-backend flashinfer with --tp-size 2 --pp-size 2 or --tp-size 1 --pp-size 4, flag set in the server environment. Reference trajectories are frozen in results/reference_trajectories.json; rerunning a config replays against the same 12 continuations.
