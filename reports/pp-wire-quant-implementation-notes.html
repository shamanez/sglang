PP Wire Codec Notes

How quantization of pipeline-parallel boundary activations is implemented in this tree · branch research/pp-activation-int8 · 2026-08-22

Short answer: this did not exist in SGLang — we built it. Upstream (main, commit 528bfac70) ships pipeline-parallel inter-stage activations as raw model-dtype (bf16) bytes unconditionally; a repo-wide sweep found no option, env var, or code path that compresses the PP wire, and main's scheduler_pp_mixin.py contains zero quantization symbols. The codec on this branch is new code, activated with SGLANG_PP_ACTIVATION_WIRE_QUANT=int8|fp8|int4 on a server launched with --pp-size ≥ 2.

1 · What stock SGLang does at a PP boundary

Each stage boundary ships one dict per microbatch through a single funnel in the scheduler: _pp_send_dict_to_next_stage() → GroupCoordinator.send_tensor_dict() (plain torch.distributed P2P over NCCL), received by _pp_recv_proxy_tensors(). The payload is hidden_states and residual, each [tokens, hidden_size] in the model dtype (some models add extras, e.g. DeepSeek's int32 topk_indices). Shape/dtype metadata is pickled over a CPU (gloo) group, so the receiver allocates whatever dtypes arrive — the transport was already dtype-agnostic, which is what made a wire codec possible without touching the protocol.

Quantization existed in stock SGLang only at other sites — none of them the PP wire:

2 · What we added

All codec logic lives in python/sglang/srt/managers/scheduler_pp_mixin.py (commits ea23f5b7a…32e70d8ef), plus one env var in environ.py:585 and a docs row. It quantizes just before the send and dequantizes just after the receive, so the model, CUDA graphs, and all math see bf16 exactly as before; only the bytes in flight change. Design points, several hardened by a post-hoc code review:

piecewherewhat it does

quantize_pp_quantize_wire_dict() :108, hooked at :1182per-token scales: int8 via the production per_token_quant_int8 Triton kernel; fp8-e4m3 via sglang_per_token_quant_fp8, shipped as uint8 (NCCL has no fp8 dtype); int4 packed two nibbles per byte. Out-of-place — the proxy dict aliases live forward state and CUDA-graph buffers. Only 2-D float tensors with rows > 0 are eligible; anything else passes through with a mixed-wire warning

Isolated roundtrip error: int8 0.66% max per-token relative, fp8 3.8%, int4 7.3%.

3 · How much communication does it save?

Each boundary crossing ships two [tokens, H] tensors, so the stock wire costs 4·H bytes per token per boundary (bf16). The codec replaces that with the quantized values plus one fp32 scale per token per tensor: int8/fp8 → 2·H + 8 bytes, int4 (two values per byte) → H + 8 bytes. At this model's hidden size (H = 2048):

wire modebytes / token / boundaryvs bf16wire savedper request, pp2 (1 boundary)per request, pp4 (3 boundaries)
bf16 (stock)8,192 B1.00×—10.49 MB31.46 MB
int8 / fp84,104 B2.00×49.9%5.25 MB15.76 MB
int42,056 B3.98×74.9%2.63 MB7.90 MB

"Per request" = one benchmark-shaped request (1,024 prefill + 256 decode tokens = 1,280 boundary crossings per token position). The scale sidecar is the entire overhead — 4 B per token per tensor, ~0.1% of the bf16 payload — so realized savings equal the format ratio almost exactly.

Converted to sustained load using each config's measured serving throughput (48-prompt bench, concurrency 16):

pp2 bf164,862139.8 MB/s—
pp2 int85,057120.8 MB/s−50% (and +4% tok/s)
pp2 int44,65619.6 MB/s−75%

Where the savings actually land: prefill. A 1,024-token prefill microbatch is 8.39 MB per boundary in bf16, transferred synchronously between stages while the pipeline fills — halving it is what cut median TTFT by 23% (pp2: 406 → 312 ms) and 21% (pp4: 297 → 234 ms). Decode transfers are only KB-scale per step, so there is nothing to save and the quant/dequant kernel launches show up as +3–4% ITL instead. On this box the absolute wire load is modest next to PCIe bandwidth — the bytes-per-token ratios are what transfer: over slower links (multi-node Ethernet/IB, the setting the literature survey targets), where the wire is a first-order cost, a 2× / 4× byte cut applies to a much larger share of step time.

Savings are only half the ledger: int8's 50% cut is quality-free in every metric we measured, while int4's 75% cut collapses GSM8K from 97% to 64% and adds +11% teacher-forced NLL — see the results report for the full six-config comparison.

4 · How to activate it

# on a machine with this branch installed (editable dev install):
export SGLANG_PP_ACTIVATION_WIRE_QUANT=int8     # or fp8 / int4; unset = stock bf16 wire

python3 -m sglang.launch_server \
    --model-path Qwen/Qwen3.6-35B-A3B \
    --tp-size 2 --pp-size 2 \
    --attention-backend flashinfer

Constraints worth knowing: the knob is ignored when pp_size == 1 (there is no wire to compress — the hosted production config, tp4, has zero pipeline boundaries); fp8 requires CUDA/MUSA (rejected at startup elsewhere); PP itself forbids speculative decoding and auto-disables the overlap scheduler; and on models whose proxy dicts carry 3-D tensors (Kimi K3, Gemma4) those tensors ship at full precision with a logged warning — a declared mixed wire.
