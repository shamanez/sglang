8-bit Activations on the Pipeline Wire

Qwen/Qwen3.6-35B-A3B · 4× RTX 5090 · sglang dev @ 32e70d8ef · run 2026-08-21

Background: what "activations" are in stock SGLang, and what this experiment changes

In a stock SGLang deployment, an activation is any tensor a layer produces during a forward pass — the hidden state flowing layer to layer, attention inputs/outputs, MLP and MoE intermediates. These all live in the model dtype (bf16 here) end to end. The only quantization stock SGLang ever applies to activations is compute-side and opt-in: with a quantized checkpoint or --quantization flag (W8A8-int8, fp8), the activation is quantized immediately before a matmul so an integer/fp8 tensor core can consume it, and the GEMM's output returns to bf16 within the same layer — the low-precision tensor never leaves the kernel call. On Blackwell datacenter parts, MoE dispatch can additionally ship expert inputs as fp8 (DeepEP), and NPU builds have an int8 TP all-reduce; on this hardware and this deployment, none of those apply.

Communication between GPUs, in stock SGLang, always carries raw model-dtype bytes. For pipeline parallelism specifically, each stage boundary ships exactly two tensors per microbatch — hidden_states and residual, each [tokens, hidden_size] bf16 — via point-to-point NCCL send/recv in the scheduler's proxy ring. There is no knob to compress that wire.

What we changed: a new research knob, SGLANG_PP_ACTIVATION_WIRE_QUANT ∈ {int8, fp8, int4}, quantizes exactly those two tensors with per-token scales just before the send and dequantizes them right after the receive. Every computation — attention, GDN state updates, MoE experts, KV cache — still runs in bf16; only the bytes in flight between pipeline stages change. The wire format is tagged (__wire_codec__) and self-describing; a bad mode value fails at server startup on every rank; zero-token idle batches and protocol collisions are guarded; and with the flag unset the code path is behavior-identical to upstream. This is deliberately the opposite site from the MXFP8/NVFP4-style work: that quantizes what GEMMs compute; we quantize what the interconnect carries.

What this experiment is

We ask what happens to the hosted model — Qwen/Qwen3.6-35B-A3B, a hybrid MoE with 30 gated-delta-net (recurrent) layers and 10 full-attention layers — when its pipeline-boundary activations are quantized to 8 and now also 4 bits at serving time. The literature survey that motivated this found that no paper measures whether such compression error accumulates across decode steps; this model's recurrent GDN state gives error a concrete mechanism to persist, so we measure exactly that. Six configurations on the same 4× RTX 5090 box (PCIe, no NVLink): tp2×pp2 (1 boundary) and tp1×pp4 (3 boundaries), each with the wire in bf16 (control), int8, and int4. The production deployment (tp4) has zero pipeline boundaries; it was restored after the runs. Isolated codec roundtrip error: int8 0.66% max per-token relative error, int4 7.3% — an order of magnitude apart, which is the point: int4 is the stressor that should expose accumulation if the mechanism exists.

Metrics and why these

Teacher-forced NLL (WikiText-2 test, 24 windows × 1,024 tokens) is the highest-resolution quality probe. GSM8K exact-match (100 questions, greedy, thinking disabled, numerically graded) is the task-level check. The positionwise probe is the accumulation instrument: 12 fixed 256-token continuations generated once by the baseline, teacher-forced through every config, recording per-position NLL, argmax agreement, and the k3-estimated KL to baseline on the shared reference tokens — the same estimator SGLang's own numerics tests calibrate with. If wire error compounded through the recurrent state these curves would degrade with position; a flat gap means per-step, non-accumulating noise. Because the reference is the baseline's own greedy trajectory, the baseline row is a favored floor (its self-agreement calibrates server nondeterminism, ~0.96–0.99 under continuous batching); the cleanest quantization read is each topology's int8/int4 row against its own bf16 control. bench_serving (48 prompts, 1,024 in / 256 out, concurrency 16) gives TTFT, inter-token latency, and throughput.

Methodology corrections since the first version of this report, found by code review: GSM8K is now graded numerically — the earlier string grading scored answers like "16.00" as wrong against gold "16", understating every config's accuracy by exactly 4 points (deltas were unaffected); and the KL panel now uses the k3 estimator on per-position logprob pairs instead of a top-5-truncated approximation.

Findings

1 — int8 quality is unaffected, at one boundary and at three. Int8 on the wire moves WikiText NLL by +0.112% at pp2 and by +0.012% at pp4 relative to each topology's own bf16 control — and the pp4 delta is smaller despite three quantized hops, which says the deltas are dominated by run-to-run noise, not by the codec. The pure topology change (pp2-bf16 → pp4-bf16) moves NLL by −0.021%, bracketing the noise floor. GSM8K (numerically graded) is 97/97 at pp2 and 97/96 at pp4 — the single dropped question is far inside the 95% Wilson interval (±5pts at n=100). Perplexity spans 6.64–6.66 across all four int8/bf16 cells.

2 — int8 shows no error accumulation over 256 decode steps. The probe's agreement-vs-position curves for the int8 configs sit inside the baseline's own self-agreement band (≈0.96–0.99, set by batching nondeterminism) at every horizon quarter, with no downward trend: pp4-int8 runs 0.964 → 0.987 → 0.986 → 0.982 across quarters while the baseline's self-agreement runs 0.974 → 0.988 → 0.980 → 0.982. Mean reference-token NLL over the probe is 0.2033 (baseline) vs 0.2037 (pp2-int8, +0.2%) vs 0.2065 (pp4-int8, +1.6%) — a constant small offset, flat in position. This is the direct measurement the surveyed literature lacks: through 30 recurrent GDN layers whose state persists across every decode step, per-token int8 wire error behaves as non-compounding per-step noise, not as drift.

3 — int4 fails, and fails multiplicatively with pipeline depth. At one boundary, int4 costs +11.0% NLL (2.103 vs 1.894; perplexity 8.19 vs 6.64) and drops GSM8K from 97% to 64%. At three boundaries it is catastrophic: +59.2% NLL (3.015; perplexity 20.4, 3.1× the control) and GSM8K collapses to 3%. The compounding is superlinear per hop — one boundary adds 0.209 nats, but three boundaries add 1.122 nats (0.374 per boundary, nearly double the single-boundary rate). The failure mode is instructive: pp4-int4 outputs remain fluent, well-formed numeric answers — surface fluency survives while multi-step arithmetic is destroyed. The isolated codec roundtrip error explains the mechanism: int4's 7.3% max per-token error (vs int8's 0.66%) is injected afresh at every boundary of every forward pass, and each stage's computation amplifies rather than absorbs it.

4 — Even int4's error does not compound across decode steps; it compounds across boundaries. The int4 probe curves are shifted far below the nondeterminism band but are flat in position: pp2-int4 agreement runs 0.846 → 0.837 → 0.868 → 0.882 across quarters, pp4-int4 runs 0.719 → 0.694 → 0.698 → 0.690. Even at int4 severity, the recurrent GDN state does not turn per-step wire noise into runaway temporal drift over 256 steps. But the per-position NLL exposes a second effect: every healthy config gets better with accumulated context (baseline NLL falls 0.308 → 0.114 from first to last quarter), while pp4-int4 stays flat at ≈1.2 — its relative gap to baseline grows from 3.7× to 10× across the horizon. Int4-corrupted activations don't just add noise; they blunt the model's ability to condition on its own context.

5 — Performance: int8 is a net win; int4 buys nothing. Halving prefill bytes cut median TTFT 23% at pp2 (406 → 312 ms) and 21% at pp4 (297 → 234 ms), and crushed the tail — p99 TTFT fell 56–58% in both topologies (1122 → 499 ms; 974 → 408 ms), because the pipeline-fill phase is where requests queue behind each other's transfers. Decode moves 1–16 tokens per hop, so the quant/dequant launch overhead slightly exceeds the bytes saved: median ITL +3.5% (13.4 → 13.9 ms) at pp2 and +3.3% (17.5 → 18.1 ms) at pp4. End-to-end, pp2-int8 is 2.4% faster with +4% throughput; pp4-int8 is a wash (+1.1% E2E, −0.3% throughput). Int4 at pp2 is strictly dominated — throughput −4.2%, E2E +5.2%, ITL +5.7%, on top of the broken quality — because its nibble pack/unpack runs as a chain of eager PyTorch ops rather than one fused kernel, costing more than the extra bytes save on intra-box PCIe. The wire arithmetic: bf16 ships 8,192 B per token per boundary; int8 4,104 B (49.9% saved); int4 2,056 B (74.9% saved). A sharper implementation would quantize only extend-mode transfers, keeping the TTFT win and dropping the ITL tax.

Verdict. Per-token int8 is a free 2× wire compression at every depth tested: no quality cost, no temporal drift, large TTFT gains. Per-token int4 is unusable at any depth — and its depth-compounding failure is exactly the accumulation phenomenon the literature had not measured. The interesting open cell between them is finer scale granularity: a 1×16-block int4/fp4 wire (NVFP4-style, for which the codebase already has kernel precedents) would cost only ~6% more bytes than per-token int4 and might recover much of the gap.

Limitations

One model (and a small one on the wire: hidden size 2,048 means only 4 KB/token/tensor — models with 7–16 K hidden dimensions stress the link 3–8× harder and may benefit more). One horizon (256 steps). One run per cell — the int4 collapse is far beyond any plausible seed variance, but the small int8 deltas are within it. GSM8K at n=100 resolves only multi-point accuracy moves. The probe is teacher-forced on baseline trajectories, so it measures representational drift, not free-running behavioral divergence beyond the first disagreement; the nondeterminism floor (≈2–3% argmax flips) caps the resolution of the agreement metric for the int8 configs (not for int4, which sits far below it). The fp8-e4m3 mode is implemented and unit-tested but not evaluated end-to-end. Int4's latency numbers are pessimistic: pack/unpack is eager PyTorch, not a fused kernel, so its throughput deficit is implementation overhead, not intrinsic. One mid-run OOM occurred (pp2-int8's probe stage, a marginal allocation failure after 100 GSM8K generations filled the radix cache at mem-fraction 0.85); the stage was rerun identically after adding an inter-stage cache flush to the harness — a memory-headroom artifact, not a codec failure, reported here because silence would overstate robustness. The original int4 driver also exited after pp2-int4 without launching pp4-int4; pp4-int4 was rerun with a corrected detached driver and its topology (pp=4, tp=1) verified from the serving process before results were accepted.

Reproduction

Branch research/pp-activation-int8. Implementation: python/sglang/srt/managers/scheduler_pp_mixin.py + SGLANG_PP_ACTIVATION_WIRE_QUANT in environ.py. Harness and driver: scripts/vast/ppq/ — run_all.sh runs all six configs (pp2/pp4 × bf16/int8/int4) and restores the production server; raw per-item JSON lives under /workspace/ppq/results/ on the box. Serving: sglang.launch_server --model-path Qwen/Qwen3.6-35B-A3B --attention-backend flashinfer with --tp-size 2 --pp-size 2 or --tp-size 1 --pp-size 4, flag set in the server environment; the harness asserts the serving process's actual pp/tp against each result label before writing. Reference trajectories are frozen in results/reference_trajectories.json; rerunning a config replays against the same 12 continuations.
