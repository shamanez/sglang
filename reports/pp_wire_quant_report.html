Quantized Activations on the Pipeline Wire

Qwen/Qwen3.6-35B-A3B · 4× RTX 5090 · sglang dev @ c1ff73797 · runs 2026-08-21/22

Background: what "activations" are in stock SGLang, and what this experiment changes

In a stock SGLang deployment, an activation is any tensor a layer produces during a forward pass — the hidden state flowing layer to layer, attention inputs/outputs, MLP and MoE intermediates. These all live in the model dtype (bf16 here) end to end. The only quantization stock SGLang ever applies to activations is compute-side and opt-in: with a quantized checkpoint or --quantization flag (W8A8-int8, fp8), the activation is quantized immediately before a matmul so an integer/fp8 tensor core can consume it, and the GEMM's output returns to bf16 within the same layer — the low-precision tensor never leaves the kernel call. On Blackwell datacenter parts, MoE dispatch can additionally ship expert inputs as fp8 (DeepEP), and NPU builds have an int8 TP all-reduce; on this hardware and this deployment, none of those apply.

Communication between GPUs, in stock SGLang, always carries raw model-dtype bytes. For pipeline parallelism specifically, each stage boundary ships exactly two tensors per microbatch — hidden_states and residual, each [tokens, hidden_size] bf16 — via point-to-point NCCL send/recv in the scheduler's proxy ring. There is no knob to compress that wire.

What we changed: a new research knob, SGLANG_PP_ACTIVATION_WIRE_QUANT ∈ {int8, fp8, int4, mxfp8, mxfp4, nvfp4}, quantizes exactly those two tensors just before the send and dequantizes them right after the receive. The first three use one scale per token; the last three are microscaled: mxfp8 (e4m3 values, one power-of-two E8M0 scale per 32 elements), mxfp4 (e2m1 values, E8M0 per 32), and nvfp4 (e2m1 values, one e4m3 scale per 16 plus a per-token fp32 global) — the OCP/NVIDIA block formats, here emulated on the wire: since every computation still runs in bf16, no MX tensor cores are required and the codecs run on any GPU, including these sm_120 consumer cards. The wire format is tagged (__wire_codec__) and self-describing; a bad mode fails at server startup on every rank; zero-token idle batches, protocol collisions, and dtype-overflow on dequant are guarded; with the flag unset the code path is behavior-identical to upstream. This is deliberately the opposite site from MXFP8/NVFP4 GEMM work: that quantizes what tensor cores compute; we quantize what the interconnect carries.

What this experiment is

We ask what happens to the hosted model — Qwen/Qwen3.6-35B-A3B, a hybrid MoE with 30 gated-delta-net (recurrent) layers and 10 full-attention layers — when its pipeline-boundary activations are quantized at serving time, along two axes: bit-width (8 vs 4 bits) and scale granularity (one scale per token vs microscaled 16/32-element blocks). The literature survey that motivated this found no paper measuring whether such compression error accumulates across decode steps; this model's recurrent GDN state gives error a concrete mechanism to persist, so we measure exactly that — and pipeline depth gives a second, independent accumulation axis (each boundary re-injects fresh quantization error into the same forward pass). Fourteen configurations on the same 4× RTX 5090 box (PCIe, no NVLink): tp2×pp2 (1 boundary) and tp1×pp4 (3 boundaries), each with the wire in bf16 (control), int8, fp8, mxfp8, int4, mxfp4, and nvfp4. The production deployment (tp4) has zero pipeline boundaries; it was restored after the runs. Isolated codec roundtrip error (max per-token relative): int8 0.66%, fp8 3.8%, mxfp8 5.9%, int4 7.3%, nvfp4 16.7%, mxfp4 ~17–20% — note the 4-bit block formats look worse than per-token int4 on this worst-case-element metric, because the e2m1 grid is coarse near its top; the quality results show why that is not the operative statistic.

Metrics and why these

Teacher-forced NLL (WikiText-2 test, 24 windows × 1,024 tokens) is the highest-resolution quality probe. GSM8K exact-match (100 questions, greedy, thinking disabled, numerically graded) is the task-level check. The positionwise probe is the accumulation instrument: 12 fixed 256-token continuations generated once by the baseline, teacher-forced through every config, recording per-position NLL, argmax agreement, and the k3-estimated KL to baseline on the shared reference tokens — the same estimator SGLang's own numerics tests calibrate with. If wire error compounded through the recurrent state these curves would degrade with position; a flat gap means per-step, non-accumulating noise. Because the reference is the baseline's own greedy trajectory, the baseline row is a favored floor (its self-agreement calibrates server nondeterminism, ~0.96–0.99 under continuous batching); the cleanest quantization read is each topology's quantized row against its own bf16 control. bench_serving (48 prompts, 1,024 in / 256 out, concurrency 16) gives TTFT, inter-token latency, and throughput.

Methodology corrections along the way, all found by code review: GSM8K is graded numerically (string grading had scored "16.00" ≠ "16" as wrong, understating every config by exactly 4 points); the KL panel uses the k3 estimator on per-position logprob pairs; and pp2-mxfp4's bench was re-measured after removing a host-sync bug from the e2m1 helpers that had contaminated its first latency numbers (quality stages unaffected; all pp4 4-bit configs ran with fixed code).

Findings

1 — Every 8-bit wire format is quality-free, at one boundary and at three. Relative to each topology's own bf16 control, WikiText NLL moves by +0.112% (int8), −0.005% (fp8), +0.015% (mxfp8) at pp2 and by +0.012%, +0.056%, +0.032% at pp4 — all smaller in magnitude than the pure topology change (pp2-bf16 → pp4-bf16: −0.021%) and, crucially, not ordered by boundary count: every 8-bit format's pp4 delta (3 boundaries) is at or below 0.06% while int8's pp2 delta (1 boundary) is 0.11%. Because the NLL measurement turns out to be bit-deterministic (see the replication section), these are real reproducible effects rather than measurement scatter — they are simply at the scale of bf16 arithmetic-reordering differences, and they do not grow with the number of quantized hops. GSM8K (numerically graded, n=100) spans 94–97% across all eight 8-bit/bf16 cells with no pattern; the 95% Wilson interval at n=100 is ±5pts. Scale granularity is irrelevant at 8 bits: per-token f32 scales and 1×32 E8M0 block scales give the same answer.

2 — No error accumulation over 256 decode steps, for any format that works. The probe's agreement-vs-position curves for every 8-bit config sit inside the baseline's own self-agreement band (≈0.96–0.99, set by batching nondeterminism) at every horizon quarter with no downward trend (e.g. pp4-int8 0.964 → 0.987 → 0.986 → 0.982 vs the baseline's 0.974 → 0.988 → 0.980 → 0.982). The microscaled 4-bit configs sit at the band's lower edge and are equally flat (pp4-nvfp4: 0.966 → 0.983 → 0.975 → 0.982; pp4-mxfp4: 0.953 → 0.973 → 0.966 → 0.966). Through 30 recurrent GDN layers whose state persists across every decode step, wire error behaves as non-compounding per-step noise — the direct measurement the surveyed literature lacks. A follow-up probe at 1024 steps (4× the main horizon, fresh references, pp4 topology) confirms it: across eight 128-step segments, int8 holds 0.979–0.991 agreement, nvfp4 0.977–0.991, mxfp4 0.965–0.981 — all flat against the baseline's 0.988–0.993 self-agreement — and even per-token int4, degraded to ≈0.70, shows no monotonic decay from segment one to segment eight. Temporal accumulation does not occur at any tested format or horizon; the only accumulation axis in this system is boundary count.

3 — Per-token int4 fails multiplicatively with pipeline depth. At one boundary, int4 costs +11.0% NLL (perplexity 8.19 vs 6.64) and drops GSM8K from 97% to 64%. At three boundaries it is catastrophic: +59.2% NLL (perplexity 20.4) and GSM8K collapses to 3% — superlinear per hop (0.209 nats for one boundary, 0.374 nats per boundary for three). The failure mode: outputs stay fluent, well-formed numeric answers while multi-step arithmetic is destroyed; and its per-position NLL stays flat at ≈1.2 while every healthy config improves with accumulated context (baseline 0.308 → 0.114 across quarters) — int4-corrupted activations blunt in-context conditioning itself, with the relative gap growing from 3.7× to 10× over the horizon.

4 — Microscaling rescues 4-bit completely; granularity, not bit-width, was the operative variable. Keeping 4-bit values but shrinking the scale block from one-per-token (2,048 elements) to microscaled blocks: mxfp4 (e2m1 + one E8M0 scale per 32) scores 96%/99% GSM8K at pp2/pp4 with +0.185%/+0.525% NLL; nvfp4 (e2m1 + one e4m3 scale per 16 + per-token global) scores 97%/97% with +0.107%/+0.052% — statistically indistinguishable from int8, at 3.54× compression. The depth behavior transforms too: int4's superlinear compounding becomes linear for mxfp4 (≈0.0035 nats/boundary at pp2, ≈0.0033 at pp4) and vanishes into noise for nvfp4. Mechanically this is the outlier-channel story: one per-token scale lets a single large channel crush the resolution of the other 2,047 values at 15 quantization levels, injecting correlated error at every boundary; a 16/32-element block containing the outlier sacrifices only its own block. nvfp4's edge over mxfp4 (finer 16-element blocks, mantissa-bearing e4m3 scales vs power-of-2-only E8M0) is visible but small.

5 — Performance: 8-bit is a net win; the 4-bit codecs currently pay an eager-implementation tax. Halving prefill bytes cut median TTFT 21–23% (int8: 406 → 312 ms at pp2, 297 → 234 ms at pp4) with p99 TTFT down 56–58%; mxfp8 matches (317/247 ms) while per-token fp8's TTFT win at pp2 is smaller (402 ms) — its quant kernel costs more on the send path at prefill scale. Decode transfers are KB-scale, so codec launch overhead appears as ITL: +3.5% (int8), +8.5% (mxfp8 at pp2) up to +37% for mxfp4 at pp4 (17.5 → 24.0 ms, throughput −20%) and +12% for nvfp4 (19.5 ms). The 4-bit numbers are implementation overhead, not intrinsic wire cost — e2m1 encode/decode runs as chains of eager PyTorch ops while int8 uses one fused Triton kernel; a fused nvfp4 wire kernel (the codebase ships NVFP4 quant kernels for GEMM inputs already) would close most of that gap, and gating quantization to prefill-only would eliminate the decode tax entirely while keeping the TTFT win.

Verdict. For a 2× wire cut, int8 or mxfp8 is deployable as-is: no measurable quality cost at any tested depth, large TTFT gains. For ~3.5×, nvfp4 preserves int8-grade quality at both depths and needs only a fused kernel to be practical. Per-token int4 is unusable at any depth — and the contrast between it and mxfp4/nvfp4 at identical bit-width is the sharpest result of the experiment: the survey's open question about error accumulation resolves as "no accumulation across time at any format; multiplicative accumulation across boundaries only when the scale granularity is too coarse for the activation outlier structure."

Limitations

One model, and a small one on the wire: hidden size 2,048 means 4 KB/token/tensor, while models with 7–16 K hidden dimensions stress the link 3–8× harder and would likely benefit more. The larger-model replication was attempted and failed on this hardware (see the replication section), so the granularity conclusion is established at one hidden size only — the mechanism (per-token scales versus outlier channels) predicts it should hold or strengthen as hidden size grows, but that is an inference, not a measurement here. The main grid uses one horizon (256 steps); the 1024-step follow-up covers pp4 only, because the pp2 equivalent OOMed (see the replication section). Replication covers four pp4 cells: NLL reproduced bit-exactly and GSM8K within 1 point, so the headline numbers are repeatable — but repeatability is not the same as robustness to seeds, hardware, or prompt sets, none of which were varied. The probe is teacher-forced on baseline trajectories, measuring representational drift rather than free-running divergence; the ≈2–3% nondeterminism floor caps agreement resolution for healthy configs. The mx/nv codecs are eager-PyTorch emulations: round-to-nearest (not round-to-nearest-even), nvfp4's global scale is per-token rather than the spec's per-tensor (finer, so our nvfp4 is mildly favored), and their latency numbers overstate intrinsic cost. pp2-mxfp4's bench was re-measured after a code-review fix removed a host-sync bug from the e2m1 helpers that had contaminated its first latency run (quality stages were unaffected; all pp4 4-bit configs ran with the fixed code). The pp2-int8 probe-stage OOM from the first campaign (a radix-cache headroom artifact, fixed with inter-stage cache flushes) and the original int4 driver dying without setsid before pp4-int4 are both reported in full in the run logs; every affected stage was rerun and topology-verified before results were accepted.

Reproduction

Harness and driver: scripts/vast/ppq/ — run_all.sh runs all fourteen configs (pp2/pp4 × bf16/int8/fp8/mxfp8/int4/mxfp4/nvfp4) and restores the production server; raw per-item JSON under /workspace/ppq/results/ on the box. Serving: sglang.launch_server --model-path Qwen/Qwen3.6-35B-A3B --attention-backend flashinfer with --tp-size 2 --pp-size 2 or --tp-size 1 --pp-size 4, flag set in the server environment; the harness asserts the serving process's actual pp/tp against each result label before writing. Per-config raw results (WikiText, GSM8K per-item, bench) and derived probe segment aggregates for all 14 configs, the 4 replicates, and both probe horizons are archived in reports/data/ so the numbers outlive the rented box. Reference trajectories are frozen in results/reference_trajectories.json; rerunning a config replays against the same 12 continuations.
